# Changelog of Deviations (M0)

Every place the build diverged from the source spec / build prompt, in one place.

## Schema
1. **`users.password_hash` removed.** Identity is Supabase Auth (ADR-001); the app
   never stores credentials (ADR-008).
2. **`users.share_percentage` (per-user TEXT `'40/30/30'`) removed.** Replaced by a
   single app constant (`app/core/constants.py`) — eliminates the drift risk the
   architecture doc flagged (§4).
3. **`commissions.review_id` polymorphic TEXT → `target_type` enum + typed FKs.**
   `review_id` / `answer_id` are now real nullable FKs with a CHECK constraint
   enforcing exactly one, restoring referential integrity.
4. **`moderation_logs` doubles as the audit log.** To honour the 15-table
   Data Dictionary (rather than add a 16th table), its `action` enum was broadened
   with admin/audit actions (`csv_import`, `payout`, `honesty_fund_distribution`)
   and it has a polymorphic `target_type`/`target_ref` + `context` JSONB.
5. **`answers.earn_eligible` retained but unwired** (ADR-006; A5 resolved as out).
6. **Denormalized aggregates updated by service-layer transactions, not DB
   triggers** — chosen for testability (architecture §4 left this open).
7. **Seller-dimension aggregates live on `users.seller_aggregates` (JSONB)**, not on
   `products`; the architecture highlight ambiguously placed seller aggregates on
   `products`, which has no seller identity.
8. **`users.id` is not FK-bound to `auth.users`** so the identical migration runs on
   local Postgres and Supabase (a Supabase-only FK may be added later).

## Parameters chosen (were undefined in spec)
9. `reputation_score` formula — ADR-003. 10. Wilson z / 45-day half-life / velocity
   10-per-hour / reciprocity 0.6-over-5 — ADR-004. 11. `verification_tier` /
   `member_type` enums — ADR-005. 12. Reverse-image (pHash) + plagiarism (pg_trgm) on-
   platform — ADR-007. 13. Rate limiting added (not in spec) — ADR-009.

## Tooling
14. **Package manager: `pip` + `requirements.txt`** (no `uv` on the build machine).
15. **`docker-compose` local Postgres 16 + Redis 7**; the same Alembic migrations
    apply to Supabase for staging (per the chosen infra approach).
16. **Migration reversibility fix:** the autogenerated initial migration's
    `downgrade()` was edited to `DROP TYPE` the named ENUMs (Alembic omits this),
    so `downgrade → upgrade` re-runs cleanly.

## Env
17. `.env` uses `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_SECRET_KEY`
    / `SUPABASE_JWKS_URL` (rebranded from the prompt's `NEXT_PUBLIC_*` names). The
    publishable key is client-safe; the secret (service-role) key is server-only.

## M1 changes (2026-07-12)
18. **Auth reversed to FastAPI-native** (ADR-010, supersedes ADR-001): `password_hash`
    **re-added** to `users`; `users.id` is now a generated PK (default
    `gen_random_uuid()`) rather than the Supabase uid; Argon2id KDF (ADR-011,
    supersedes ADR-008). Supabase JWKS no longer used for request auth; RLS is now
    dormant defense-in-depth.
19. **New tables (schema grew from 15 → 17):** `membership_tiers` (tier config;
    ADR-012) and `review_versions` (edit history). This is a scope expansion from
    the "15-table Data Dictionary" constraint, driven by the M1–M3 milestones in
    `MILESTONES.md`.
20. **New `users` columns:** `password_hash`, `is_suspended`, `membership_tier`
    (enum special/founding/standard, default standard). `reviews.current_version`.
21. **`questions.best_answer_id` FK** materialized in the M1 migration (deferred via
    `use_alter` in M0).
22. **AI critique** (ADR-013): default provider `stub` (no key); Claude/OpenAI
    providers behind a swappable interface. New deps: `argon2-cffi`, `anthropic`,
    `email-validator`.
23. **Rate limiter switched to a synchronous Redis client, fail-open** — the async
    client broke under the test client's event-loop lifecycle, and auth must never
    hard-fail on a Redis outage.
24. **Alembic autogenerate missed the `users.id` server_default and the shared
    `membership_tier` enum's single-create** — both fixed by hand in the M1
    migration (`f18b59a2227b`).

## Production / Supabase (2026-07-12)
25. **`SUPABASE_CONNECTION_STRING` + `USE_SUPABASE` toggle** (config): when
    `USE_SUPABASE=true`, runtime and Alembic target Supabase. The string is
    normalized through SQLAlchemy (`postgres://`→`postgresql+psycopg://`, password
    special chars re-encoded), and `sslmode=require` (plus prepared-statement
    disabling for the transaction pooler) is applied automatically.
26. **Supabase direct endpoint is IPv6-only** — `db.<ref>.supabase.co` does not
    resolve from IPv4-only networks (incl. this dev machine and typical CI). The
    **Session-mode pooler** string must be used to migrate from IPv4. Documented in
    `PRODUCTION.md`; helper `scripts/db_check.py` verifies reachability.
27. **Production startup guard** (`main.py` + `Settings.production_issues()`): when
    `APP_ENV=production`, the app refuses to boot with a weak `JWT_SECRET`, a
    localhost DB, or wildcard CORS. A strong `JWT_SECRET` was generated into `.env`.
28. **`ENABLE_DOCS`** toggle to hide `/docs` in production.
29. **RLS enabled on `public.alembic_version`** (migration `0003_rls_alembic_version`)
    — Alembic's bookkeeping table is in `public` and thus exposed to Supabase's
    PostgREST; RLS (not FORCEd, so the migration role still bypasses) clears the
    Supabase "RLS disabled in public" Critical advisor. No `public` table is now
    without RLS. Note: the `storage.*` tables the dashboard shows are Supabase's own
    managed Storage schema, not ours — our app lives entirely in `public`.

## M2 slice 1 — referral link flow + publication gate (2026-07-13)
30. **Publication gate SUPERSEDES capstone FR-3 "publish immediately".** A new
    review is hidden (`reviews.published_at IS NULL`) and auto-queued
    (`earn_eligible_status=pending`); a moderator publishes it — pasting a referral
    link monetizes **and** publishes atomically, or an explicit no-link publish is
    used for ≤2★ (Honesty Fund) / non-monetizable platforms. Product aggregates now
    count **published** reviews only. Existing reviews backfilled
    `published_at = created_at` (don't hide live content). Spec:
    `superpowers/specs/2026-07-13-referral-link-flow-design.md`.
31. **Schema 18 → 19 tables:** `referral_links` (link history, one active per review
    via a partial unique index, RLS on). Enum growth: `platform += amazon`;
    `moderation_action += affiliate_link_attach/affiliate_link_revoke/publish/unpublish`;
    new `referral_link_status`. Migration `0004_referral_links` (enum ADD VALUE in an
    autocommit block; downgrade can't drop enum values — documented).
32. **Attribution redirect `GET /r/{review_id}`** (root-mounted, public) records a
    `sessions` click row (PII deadlines via `services/pii`) then 302s. The raw
    affiliate URL is never exposed — `ReviewOut.referral_redirect_url` is the only
    public link. Invalid client IPs (e.g. TestClient's `testclient`) are stored NULL.
33. **Added guard beyond the spec:** attaching a link requires
    `verification_status=verified` (`409 review_not_verified`) — monetizing an
    unverified review would contradict FR-3.
34. **M1 tests updated** for the gate (reviews no longer public on submit; version
    history of an unpublished review requires author/moderator auth).
